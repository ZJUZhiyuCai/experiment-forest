## 3. 设计取向（保持既有风格）

- **四层状态如实分开，用同一套词**：
  `输入框（未记下，只在本窗口）` → `本页正文（已写入，待保存）` → `Host（已保存 r#）` → `Obsidian（已同步 / 等待同步 / 冲突）`。
  页头保存徽章改成“这页现在到哪一步”的入口：显示最靠前、仍需处理的那一层；点开是一张小卡，四层逐行写明真实状态，需要操作的地方直接给按钮（记下、立即保存、核对）。
- **就地审阅**：页首只留一条精简提案条，包括模型自述（明确标为自述）、Host 系统记录、批量勾选与“下一处 ↓”。每处改动挂在它要替换的那一块正下方；追加类改动放在页末。文字和标题类改动显示**逐字差异**：删掉的字划线标红，新增的字标绿，数字、单位、样品号一旦被改就会被高亮出来。表格与素材保持左右对照。逐条接受、系统核对警告、依据标签、原子批量说明、推断类默认折叠，这些全部保留。
- **去紫**：AI 相关统一改用“墨色”（中性石墨）。浅色主题是纸白上的墨，深色主题反过来；森林绿仍是全站唯一的品牌强调色。“接受”与“已接受”细线同为绿色，表示“你的决定”。“理一理”改成墨色胶囊。两条渐变光带去掉，换成发丝线。
- **Obsidian 就地入口**：点页面上的 Obsidian 标签，展开这篇笔记的小卡，里面有相对路径、单页真实状态，以及仅在 `synced` 时出现的真实 `<a href={uri}>`“在 Obsidian 中打开”和“复制笔记链接 [[…]]”。卡片里保留“同步设置与详情”。如果页面有未保存内容或未记下的输入，卡片会说明“Obsidian 里是上次保存的版本”。不会自动打开原生应用。
- 不加新功能面：没有新的页面、设置或数据结构。

## 6. 实施结果（实际改动）

实际只改了第 4 节所列的 6 个客户端文件。没有运行任何命令，没有类型检查，没有在浏览器里看过效果。以下内容都是代码层面的改动，没有经过实测验证。

### ExperimentPage.tsx
- **输入框**：删掉了组件内的 `useState draft`。现在 `value` 绑定 `state.composer`，`onChange` 调 `ctrl.setComposer`，回车或“记下”调 `ctrl.commitComposer()`（失败时由控制器保留原输入并设置 notice）。剪贴板 TSV 直接成表、粘贴文件仍走原路径，没有改动。
- **未记下提示**：输入框有字时，工具栏出现“○ 未记下”，悬停可看完整说明；卡片外圈加一道极淡的暖色描边。“理一理”按钮在只有输入框有字时也可用，按钮提示写明发送前会先记下。
- **保存徽章 → “这页到了哪一步”**：正文已保存、但输入框还有字时，徽章显示“输入框未记下”（空心暖色点），不再只说“已保存”。点开小卡，四层逐行写出真实状态：输入框 / 本页正文 / Host（r# 与时间）/ Obsidian。需要操作的层直接给按钮：记下、立即保存、核对。另保留了读屏用的 `role="status"`。
- **Obsidian 标签 → 笔记小卡**：状态优先取 `obsidianNoteTarget(...).state`。仅在 `synced` 时出现真实的 `<a href={target.uri}>`“在 Obsidian 中打开”和“复制笔记链接”（剪贴板被拒时，退到选中的只读输入框，由用户手动复制）。`pending` / `conflict` 不提供打开入口，也不说“已同步”。页面有未记下或未保存的内容时，标签显示“Obsidian 是上次保存的版本”。宿主没有给出 target 时（例如仓库不在注册列表中），沿用原来的时间对比，并写明“暂时不能从这里直接打开”。卡底保留“同步设置与详情”和单向同步提醒。不会自动唤起原生应用。
- **就地审阅接线**：每块后面挂上该块的待定改动，页末是追加类改动。“逐处看 / 下一处”会滚动到对应改动并轻闪一下。到达横幅提供“从第一处开始”。
- 通用小弹层 `Pop`：点外面关闭用的是 `composedPath()`，在 shadow root 里也能正确判断。按 Esc 只关弹层，焦点回到触发按钮，不会关闭页面。

### ProposalReview.tsx
- 页首 `ProposalTray` 现在只是精简提案条：模型自述（长文默认两行，可展开，仍明确标为自述）、系统记录、“改动已放进正文：N 处在要改的那块下方，M 处追加在页末”、“逐处看”，以及有多处时的全选和批量接受 / 拒绝（保留原子说明）。
- `InlineOps` / `usePlacement` / `useReviewSelection`：改动按正文顺序就地渲染。勾选状态在正文和提案条之间共享。只剩一处时不显示“下一处”。
- **逐字差异**：文字和标题的替换显示删去（红底、划线）与新增（绿底）。数字和拉丁词整体成词，所以 0.23 → 0.32 会显示为一整处替换。超过计算预算时，退化为“整段删去 + 整段新增”，结果仍然正确。“先改再接受”打开编辑，差异随输入实时更新；“还原模型原文”保留。表格、素材、追加类仍用原来的左右对照或单栏。
- **新增的确定性提醒**（只陈述差异事实，不做语义判断）：差异里有数字被改动或删去；模型自报为“排版”，却改了数字或删去了 N 个字。原有的系统核对、目标或依据已变化、图片依据待核提醒都保留。
- 已处理的提案收进“已处理的提案 N”，改动默认折叠。`ReceiptPanel` 导出不变（`OriginalView` 仍在用）。

### OrganizePage.tsx
- `go` 改用 `ctrl.prepareOrganize()`。失败时显示 `ctrl.getState().notice?.text`（没有时用一条兜底说明），并保留用户填写的整理要求。
- 发送前预告：会先做哪几步（记下输入框里的「…」、保存到 Host、等 N 个文件登记完成），以及“模型读取 Host 上保存好的这一版：X 块 · 素材 Y 个”。按钮文案为“先记下并保存…”。
- `copyToClipboard` 改为导出，供笔记小卡复用。到达横幅新增可选参数 `onReview`。

### ForestApp.tsx
- 顶栏“已同步 hh:mm”改为“已刷新 hh:mm”（以及“刷新中”“刷新失败”“未刷新”）。悬停提示写明这是从 Host 刷新的列表数据，不表示某一页已保存，也不表示 Obsidian 已同步。

### icons.tsx
- 新增 `external` 图标。

### forest.css
- 去紫：4 组主题令牌里的 `--fa-ai*` 改为墨色（浅色主题 #3a3a3c / 实底 #1d1d1f；深色主题 #d4d4d4 / 实底 #ececec，墨水色 #191919）。复选框焦点环改为森林绿。新增 `--fa-diff-*` 四个令牌。全文件已检索，没有残留的紫色色值。
- 提案卡改为纸色浅底，去掉“紫→绿”光带和紫色辉光；新提案用绿色细环提示。理一理面板去掉光带。“理一理”改为墨色胶囊，“发送”跟随。“接受”改为柔绿。“待核”改为墨色实底小签。等待横幅中性，提案到达时用浅绿底。侧栏“待核对”计数的白字改用令牌，避免深色主题对比度不足。
- 新增样式：就地改动卡、差异标记与图例、四层状态卡、Obsidian 笔记小卡、输入框“未记下”提示。补了窄栏（≤ 520px）适配和强制配色回退（新增文字改用下划线）。
- 经典详情、今天、执行清单等视图里的 AI 标签也跟着令牌变成墨色，这些视图没有单独核对过视觉效果。

## 8. 确切的接口缺口 / 需求（交给 Codex 判断，前端没有伪造）

1. **必需**：`ROOT-CONTRACT.md` 里的 pageStore 接口与 `client/obsidian-note.ts`，前端已按合同使用。另希望 `unsavedLabel()` 描述输入框时用“未记下”一词，与界面统一，例如“输入框有未记下的文字”。
2. **可选**：`obsidianNoteTarget` 增加单篇 `syncedAt`。现在 `synced` 时显示的“上次同步 hh:mm”取的是全库 `lastSyncedAt`，文案只写“上次同步”，没有说成单篇时间。
3. **可选**：`commitComposer()` 返回新建块的 id（或 `{ ok, blockId }`）。这样记下后可以轻闪新块，让用户确认写进了哪里；现在没有做这个反馈。
4. **说明**：未记下的输入只在当前 Harness 窗口里保留，界面已如实写明。如果需要跨会话保留，得由 Host 提供草稿存储，本轮不假设有。
5. 没有改任何正确性层。差异与“数字被改动”的提醒只是展示层对两段文字的确定性比较，接受与否、版本校验仍以 Host 的 `decideProposal` 为准。
