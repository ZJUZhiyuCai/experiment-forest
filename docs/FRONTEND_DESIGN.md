## 0. 设计立场：一片不说谎的森林

在开始画界面之前，先立下 6 条不可协商的原则。后面所有设计都要对照它们检查。

1. **屏幕上的每个数字都可追溯。** 每个统计值都能点开，看到它由哪些记录算出。系统无法计算的值不显示，绝不写死。（对应 R§2.1）
2. **没填就是没填。** 未知、空、零、否是四种不同状态。前端不替用户补任何实验参数，不预选可能出错的默认值（例如存储温度、无菌结果）。（R§2.3）
3. **说“已保存”之前，必须真的已保存。** 只有服务端确认后才显示成功；失败要能看到、能重试，草稿不丢。（R§3.1）
4. **AI 是助手，不是作者。** 模型只由宿主提供。宿主不可用时如实告知，不用模板冒充。模型的产出一律先作为“建议”，需要用户逐条采纳，采纳后留下来源标记。（R§2.2、R§4.3）
5. **森林是数据的投影，不是奖励系统。** 树、年轮、林相都由真实记录驱动，可以切换为表格查看，不发虚构勋章，不弹阻塞式庆祝动画。（R§2.5）
6. **为实验台设计。** 戴手套、单手操作、站着、被打断都是常态。所以要有快速记录入口、大点击区、键盘直达，任何时候都能离开页面而不丢东西。

## 1. 产品概念：「林间记录本」

**标本馆 × 野外记录本。** 视觉灵感来自植物标本馆的标本签、野外考察笔记本的方格纸，以及中式实验记录本的落款盖章。目标是让“实验小森林”从“可爱主题”转变为**严谨又有温度**的科研辨识度。

### 1.1 隐喻映射（只用于命名与视觉，界面主标签一律用科研术语）

| 科研实体 | 森林意象 | 视觉载体 | 规则 |
|---|---|---|---|
| 课题 | 一棵树 | 年轮徽记 RingGlyph | 年轮圈数 = 有已完成记录的月份数 |
| 实验记录 | 树上的一圈年轮 / 一节新枝 | 生长线 GrowthLine 上的节点 | 节点形状表示状态（计划/进行中/完成/修订） |
| SOP | 根系 | 课题页的“根系”栏 | 记录引用 SOP 的某个**版本**，根系连到具体版本 |
| 样本 | 种子库 | 标本签 SpecimenLabel、冻存盒格 | 每次使用都写入流水，余量由流水计算 |
| 助手 | 林务员「小森」 | 右侧面板 | 只陈述、建议、引用用户自己的数据 |
| 完成并锁定 | 落章 | 印章 SealStamp | 锁定后只能“修订”，需要填写原因并保留历史 |

主导航写“实验记录”，不写“幼苗”；“种子库”只作为样本库页的副标题出现。隐喻负责增添温度，不能增加理解成本。

### 1.2 核心工作流（以课题→实验记录→SOP/样本为主干）

```
 课题 ──┬── 实验记录（按 SOP 版本执行 · 消耗样本 · 产生数据）──► 完成·落章 ──► 修订（留痕）
       │        ▲            │                │
       │        │            ▼                ▼
       │     快速记录      样本使用流水      续作（下一次实验引用上一次）
       │
       ├── SOP 根系（版本化，“以此 SOP 开始实验”）
       └── 样本（种子库，冻存位置，过期/低存量提醒）
```

| 形态 | 容器宽度 | 布局 |
|---|---|---|
| 面板 | < 640px | 单列；底部 5 键导航栏；助手和元数据以底部抽屉呈现 |
| 标准 | 640–1199px | 左侧 56px 图标轨 + 主区；助手作为覆盖式右抽屉 |
| 宽屏 | ≥ 1200px | 左侧 232px 导航（含课题树） + 主区 + 右侧 360px 上下文栏（助手/元数据/关联，可收起） |

## 4. 关键页面

每个页面都要定义 5 种状态：**加载**（超过 300ms 才显示骨架，不加人为延迟）、**真实空态**、**错误**（可重试、可展开详情）、**不可用**（服务端或宿主能力缺失）、**冲突**（并发写入）。

- **生长线 GrowthLine**：横轴是真实日期；节点是记录；“续作”关系画成分枝。悬停或聚焦显示标题、状态、SOP 版本，点击进入记录。支持键盘左右键逐个节点移动。
- **年轮徽记 RingGlyph**（课题头像）：每一圈代表一个“有已完成记录的月份”，圈的粗细按该月完成数取对数映射。`title`/`aria-label` 写明具体数字，例如“2026 年 9 月：4 条完成”。没有记录时只显示一个空心圆点。
- **根系·SOP 栏**：列出本课题用到的 SOP 及**具体版本**，每个版本旁显示“被 N 条记录使用”。
- **概况栏**：只放可计算的事实，包括记录状态分布、用过的样本、偏差次数、最近 30 天活动。不提供“进度 %”，除非用户明确定义里程碑；手填进度如果要保留，必须标注“手动设定”。
- **“开始实验 ▾”**：可选空白记录、按某个 SOP 版本开始，或“续作”某条已有记录（预填课题、SOP、样本关联，但不复制结果）。

### 4.3 实验记录（编辑 · 执行 · 阅读 · 修订）

记录是整个产品的核心。设计原则：**直接创建，原地编辑，自动保存，完成即锁定。** 不再使用“大表单 + 提交”的模式。

```
┌ REC-2026-0142 ·  Western Blot 检测 p-AKT                      ● 已保存 14:02:31 ┐
│ 课题 CAR-T 杀伤 ▾ · 分类 分子生物学 / Western Blot ▾ · 日期 2026-11-07 · ◐ 进行中   │
│ ┌ 标本签 ───────────────────────────────────────────────┐                      │
│ │ 编号 REC-2026-0142   执行人 张三   SOP-007 v1.3   续作自 REC-0138 │  [完成并落章] │
│ └──────────────────────────────────────────────────────┘                      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 目的 / 假设          （可折叠段落，Markdown + 公式）                              │
│ 材料与样本           S-0231 抗 p-AKT   用量 [ 2 ][µL ▾]  批号…   [+ 关联样本]      │
│ 步骤（来自 SOP-007 v1.3 快照）                                                   │
│   ☑ 1 制胶 10%                      13:05                                       │
│   ☑ 2 上样 20 µg/孔                 13:40                                       │
│   ☒ 3 转膜 100V 90min  ⚑ 偏差：实际 75min，原因「电源报警」        13:50          │
│   ☐ 4 封闭 5% BSA 1h                                                           │
│ 随记时间流                                                                       │
│   14:20  加入一抗 1:1000，4℃ 过夜            （来自快速记录）                       │
│ 原始数据与附件       [拖入图片/表格/仪器导出文件]   【待契约：附件存储】                     │
│ 结果 · 结论                                                                      │
├──────────────────────────────────────────────────────────────────────────────┤
│ 关联：前序 REC-0138 · 后续 — · 引用 SOP-007 v1.3 · 样本 2                          │
└──────────────────────────────────────────────────────────────────────────────┘
```

**状态机**（由服务端裁决，前端只发起转换）：

```
 计划 ──开始──► 进行中 ──完成并落章──► 已完成(锁定) ──修订(填原因)──► 修订中 ──再次落章──► 已完成 r2
   └──────────────── 作废(填原因，保留可见) ◄───────────────┘
```
- **完成并落章**之前先给出“完整性检查”清单，列出未勾选的步骤、没有单位的数量、空的结果段。清单**只提示，不阻塞**（标题和日期除外），也不会自动补任何内容。确认后显示**印章 SealStamp**：「已落章 · 2026·11·07 14:31 · 张三」。
- **锁定后**：正文只读；“修订”会创建新的修订版，必须填写原因；在修订历史里可以逐段对比差异。
- **SOP 快照**：开始实验时把 SOP 的步骤复制到记录里（包含 SOP 版本号）。之后 SOP 再修订，不影响已开始的记录；记录页会提示“SOP 已有 v1.4”。
- **数量输入 QuantityInput**：数值和单位都必填；单位从受控列表中选择；样本用量经服务端事务扣减余量。单位不兼容时会提示，而不是悄悄换算。
- **元数据**（温度、pH、重复数、对照、随机化）全部**显式可见、默认空白**，以“实验条件”卡片的形式按需添加。只有被添加并填写的字段才会写入记录。（修复 R§2.3）
- **自动保存**：输入停止 800ms 后提交。每次提交带上服务端返回的版本号（例如 ETag 或 version）。版本冲突时打开冲突视图，左右对比，由用户选择保留哪一方。网络失败时把内容写进本地草稿缓冲区（见 §6.4），并显示“未同步”。

### 4.4 SOP 库

```
┌ SOP ────────────────────────────── [新建 SOP] [从模板新建] ┐
│ 筛选：全部 · 生效中 · 草稿 · 已停用 · 模板库      ⌘K 内搜索   │
│ SOP-007  Western Blot 通用流程   v1.3 生效中  被 23 条记录使用 │
│ SOP-012  原代 T 细胞分离         v0.4 草稿                  │
│ 模板 · 细胞培养标准操作（参考模板，需审阅后使用）               │
└──────────────────────────────────────────────────────────┘
```
- **版本化**：修改生效中的 SOP 会生成新的草稿版本，“发布”后成为生效版本，旧版本保留且只读。可以在任意两个版本之间对比差异。
- **状态**只有“草稿 / 生效中 / 已停用”三种。不提供可以自选的“已批准”。如果服务端以后支持审批人，再加“待审 / 已审（审批人、时间）”。
- **模板库**：沿用旧版 5 份模板正文，统一标注“参考模板”，作者显示“模板”而不是某个人。用模板新建时生成**草稿**，不能直接生效。
- **以此 SOP 开始实验**：在 SOP 页可以选择课题并直接创建一条“进行中”的记录。

### 5.3 网格、密度、形状
- 4px 基线，8px 栅格。正文 14px，行高 1.6；表格 13px。提供“紧凑 / 舒适”两档密度，样本表和记录总表默认紧凑。
- 圆角统一：控件 6px，卡片 10px，标本签 2px（像纸签）。删除随机不对称圆角和背景 blob。
- 阴影只用于浮层（菜单、抽屉、对话框）。页面层级靠 `--line` 和底色差来区分。
- 背景可以加一层极淡的方格纸纹理（CSS 渐变实现，透明度约 3%），只出现在 `--canvas` 上，表格和输入区不加。

### 5.4 图标
- 内置 SVG 图标集（线性、1.5px 描边），替换 Font Awesome CDN。
- 自绘 6 个植物学字形：种子（空态）、新芽（新建）、年轮（课题）、根系（SOP）、冰晶（冷冻）、印章（锁定）。线稿风格，单色，跟随 `currentColor`。

### 5.6 动效（诚实的动效）
- 动效只用来确认**真实发生**的状态变化：保存成功时，保存状态点做一次 150ms 的淡入；落章时印章做一次 180ms 的按压缩放（1.08→1）；新记录在生长线上从地面“长出”（240ms）。
- 不使用循环动画、漂浮云朵、彩带，也不做模拟加载的骨架。
- 全面遵循 `prefers-reduced-motion`，开启时只保留透明度变化。

## 6. 数据真实性在界面上的落实机制

### 6.1 字段级来源（provenance）
每个可编辑字段都带 `source` 标记：`user | import | legacy-default | assistant-suggested | assistant-accepted | computed`。界面只在**非 `user`** 时显示角标，避免噪音。导出时保留来源标记。【待契约：服务端存储形式】

### 6.2 空值语义
前端类型严格区分 `null`（未填）、`""`（不允许，保存前会规范化为 `null`）、`0` 和 `false`。表单控件不预选可能出错的选项。列表里未填写的值显示为 `—`，不显示为“0”或“否”。

### 6.3 写入可信
- 只有服务端返回 2xx 才更新为“已保存”。完成、落章、样本扣减、删除这类**关键写入不做乐观更新**。勾选步骤、展开折叠这类低风险操作可以乐观更新，失败时回滚并提示。
- 删除改为“移入回收站”，30 天内可恢复（前提是服务端支持【待契约】）。不支持时，删除确认对话框要列出影响范围，例如“将解除 4 条记录的课题关联”。不再使用 `window.confirm`。

### 6.4 本地草稿缓冲区（唯一允许的本地持久化，界面偏好除外）
- 用途仅限于防止丢稿：网络失败或页面关闭时，把未同步的编辑以 `{实体, id, 基线版本, 补丁, 时间}` 的形式存入 IndexedDB。
- 界面上明确显示“本地草稿（未同步）”。重新进入时提示恢复、查看差异或丢弃。草稿永远不作为数据源展示在列表或统计中。

### 6.5 统计可下钻
“今日”和“概况”里的每个数字都是链接，点开就是一个已经筛选好的列表。例如“3 条草稿超过 7 天未更新”会打开“记录 · 状态=草稿 · 更新早于 7 天前”。

### 6.6 身份
作者、执行人、操作者来自宿主或服务端身份【待契约】。前端不提供“作者”文本框；身份缺失时显示“未知用户”，并提示配置。

### 6.7 时间
- “实验日期”是本地日历日（`YYYY-MM-DD`），由 `Temporal`/`Intl` 按本地时区计算，**禁止使用 `toISOString().split('T')[0]`**（修复 R§2.4）。
- 事件时间戳一律使用带时区偏移的 ISO 8601，展示时按本地时区格式化。只有日期的字段不显示时分。

- **沿用：** React 18、TypeScript、Vite、zod、marked、DOMPurify、KaTeX、highlight.js（按需加载语言包）。
- **建议新增：**
  - `@tanstack/react-query`：服务端状态、缓存失效、重试、并发控制。可以替代旧的 sessionStorage 缓存层。
  - `react-router`：使用 Hash 或 Memory 模式。
- **样式：** 继续用 Tailwind 3，但 `theme` **只暴露令牌**，关闭默认色板，防止原生色值回流。
- **移除：** framer-motion（动效用 CSS 足够）、reactflow/dagre/d3 全家桶（首版不做导图）、sonner（改用内置的可访问 Toast），以及 Font Awesome CDN。
- **可选降级：** 如果不批准新增依赖，可以用约 150 行代码实现最小的 query 缓存（基于 `useSyncExternalStore`），但并发和重试能力会弱一些。

### 7.3 宿主适配层（只定义需求，不猜测 SDK）

```ts
// host/HostBridge.ts —— 前端视角的“能力清单”，实际映射等官方契约核验后实现
export type Capability<T> =
  | { status: 'available'; value: T }
  | { status: 'unavailable'; reason: string };   // 用于诚实展示，绝不降级为模拟

export interface HostBridge {
  /** 模型对话：流式输出；输入为前端组装的消息与“上下文芯片”内容 */
  model: Capability<{
    stream(req: AssistantRequest, signal: AbortSignal): AsyncIterable<AssistantChunk>;
    describe?(): { displayName?: string };       // 若宿主允许展示模型名【待契约】
  }>;
  /** 当前用户身份（用于执行人/操作者/审计） */
  identity: Capability<{ userId: string; displayName: string }>;
  /** 主题信号 */
  theme: Capability<{ scheme: 'light' | 'dark'; subscribe(cb: (s: 'light'|'dark') => void): () => void }>;
  /** 深链/导航同步（插件内路由 ↔ 宿主地址） */
  navigation: Capability<{ current(): string; push(path: string): void; subscribe(cb: (p: string) => void): () => void }>;
}
```
- 页面和功能模块只消费 `HostBridge`，不允许直接引用宿主的任何全局对象。
- 某项能力 `unavailable` 时，对应界面显示 §4.9 中的诚实状态。
- `AssistantRequest` 里的上下文内容必须与界面上勾选的芯片**一一对应**（单元测试强制校验）。

### 7.4 路由
- 宿主若以 iframe 或 webview 加载固定入口：用 **HashRouter**，`base` 设为宿主给定的路径。
- 宿主若提供导航 API：用 **MemoryRouter**，并通过 `HostBridge.navigation` 双向同步深链。
- 两种方式都**不依赖服务端路由重写**（修复 R§4.4）。最终选择【待契约】。

### 7.5 服务端交互约定（前端期望，待与 Codex 对齐）
- 资源化接口：`topics / records / sops(+versions) / samples(+usages, +locations) / search / import(dry-run, commit) / export`。【待契约】
- 并发：读接口返回 `version` 或 `ETag`，写接口带上 `If-Match`；返回 409 时附带当前服务端版本，供冲突视图使用。
- 错误格式统一为 `{ code, message, details? }`。前端按 `code` 映射为中文提示，同时保留原始信息供用户展开查看。
- 分页统一用游标；列表的排序和过滤都在服务端完成。
- 编号（如 `REC-2026-0142`）由服务端生成，前端不生成业务编号。

### 7.6 可访问性
- 所有交互都能用键盘完成；焦点环可见（2px `--moss` 外描边）；对话框和抽屉管理焦点并锁定滚动。
- 年轮、生长线、林相都提供等价的表格视图和 `aria-label` 数值描述。
- 状态不只靠颜色区分：生长线节点同时使用不同形状（○ ◐ ● ◆）。
- 实验台模式（设置项）：点击区 ≥ 44px，字号 +2，适合戴手套用平板操作。

### 7.7 性能预算（实现阶段验收）
- 首屏 JS（gzip）≤ 180KB；Markdown、KaTeX、highlight 按需加载。
- 面板形态冷启动到可交互 ≤ 1.5s（以中端笔记本为基准，实际以宿主环境测量为准）。
- 超过 200 行的列表使用虚拟滚动（样本表、记录总表）。

```ts
type ISODate = string;      // 本地日历日 YYYY-MM-DD
type ISOTime = string;      // 带时区偏移的时间戳
type Source = 'user' | 'import' | 'legacy-default' | 'assistant-suggested' | 'assistant-accepted' | 'computed';
type Sourced<T> = { value: T | null; source: Source };

interface Topic { id: string; code: string; title: string; question: Sourced<string>;
  status: 'planning' | 'active' | 'paused' | 'closed' | 'archived'; ownerId: string;
  createdAt: ISOTime; updatedAt: ISOTime; version: string; }

interface ExperimentRecord { id: string; code: string; topicId: string | null; title: string;
  category: CategoryKey; date: ISODate; executorId: string;
  status: 'planned' | 'in_progress' | 'locked' | 'amending' | 'voided';
  revision: number; followsRecordId: string | null;
  sopSnapshot: { sopId: string; version: string; steps: Step[] } | null;
  sections: { purpose?: Md; materials?: Md; results?: Md; conclusion?: Md };   // Md = { text: string; source: Source }
  conditions: Array<{ key: string; value: Sourced<number | string>; unit?: Unit }>; // 只含用户添加的条件
  timeline: Array<{ at: ISOTime; text: string; source: Source }>;               // 随记时间流
  sampleUsages: Array<{ sampleId: string; amount: number; unit: Unit; usageId: string }>;
  lockedAt?: ISOTime; lockedBy?: string; version: string; }

interface Step { index: number; text: string; doneAt?: ISOTime; deviation?: { note: string } }

interface SOP { id: string; code: string; title: string; category: CategoryKey; isTemplate: boolean;
  currentVersion: string; status: 'draft' | 'active' | 'retired'; }
interface SOPVersion { sopId: string; version: string; body: Md; steps: Step[];
  publishedAt?: ISOTime; publishedBy?: string; usedByCount: number; }

interface Sample { id: string; code: string; name: string; type: SampleType;
  status: SampleStatus; storage: StorageCondition | null; location: LocationRef | null;
  initial: { amount: number; unit: Unit } | null; remaining: { amount: number; unit: Unit } | null; // remaining 为计算值
  expiry: ISODate | null; qc: { sterility: 'untested' | 'pass' | 'fail'; mycoplasma: 'untested' | 'pass' | 'fail' };
  topicIds: string[]; version: string; }
interface SampleUsage { id: string; sampleId: string; recordId: string | null;
  kind: 'use' | 'adjust' | 'receive'; amount: number; unit: Unit; reason?: string; at: ISOTime; by: string; }
```

## 9. 旧数据迁移映射

**入口：**
1. 用户在旧版“设置 → 导出”得到 JSON。注意它只包含 records、notes、sops 三类（R§3.2）。
2. 推荐方式：新前端提供“从本浏览器迁移”，**只读**地扫描旧版 localStorage 键，生成迁移包，再走 §4.8 的预览和提交流程。前提是新旧版本同源，否则引导用户在旧版页面里用一段只读导出脚本导出。【待确认部署形态】

| 旧键 / 字段 | 新实体 | 规则 |
|---|---|---|
| `projects` | Topic | `title`、`description` 映射为 `question`（`source: import`）；`leader` 不映射为 owner，只存为备注“旧负责人：xx”（身份来自服务端）；`progress` 丢弃或存为“旧版手动进度” |
| `experiment_records` | ExperimentRecord（状态 `locked` 或 `planned`） | `completed` → `locked`（`lockedBy` 记为“旧版导入”）；`draft` → `in_progress`；`archived` → `locked` 并打上归档标签；`content` → `sections.results`（`source: import`） |
| └ `qualityControl.replicates=3`、`randomization=true` | conditions | 标记为 **`legacy-default`**，界面显示“旧版默认值 · 待复核”（R§2.3） |
| └ `experimentalConditions`（温度/湿度/pH） | conditions | 有值时同样标记为 `legacy-default` |
| └ `dataValidation.isValidated` | — | **丢弃**（旧版无条件写入，没有含义） |
| `experiment_notes` | 记录随记时间流，或课题随记 | 有 `relatedRecordId` 的追加到该记录的 `timeline`，否则作为课题级随记 |
| `sops` | SOP + SOPVersion | 每条生成 v“旧版本号”的一个版本；状态统一设为 `draft`（旧版的“已批准”没有审批依据），备注里保留旧的 `approvalStatus` |
| `samples` | Sample | `qualityControl.sterility=false` → `untested` + `legacy-default`；`storage.condition` 原样导入但标注待复核；`quantity.volume` 作为 `initial`，没有单位时提示补充 |
| `sample_history` | SampleUsage | `used` → `use`；被误标为 `moved` 的删除事件 → 丢弃；`userId: '系统'` → `by: 旧版导入` |
| `experiment_plans` | 计划状态的记录 | `plannedDate` 映射为 `date`，状态设为 `planned` |
| `calendarEvents` / `scheduleEvents` / `todoItems` | 可选：转为计划状态的记录，或跳过 | 预览中让用户逐类选择 |
| `aiChatSessions` | 不导入（可选：导出为只读 Markdown 存档） | 旧会话来源不可信（可能是模板回复） |
| `aiSettings` | **绝不导入** | 包含 API Key；迁移报告中明确写出“已忽略” |
| `dailyMood*`、`userProfile`、`theme` | 跳过（`theme` 可映射为界面偏好） | — |

迁移完成后提示：“旧版数据仍保留在本浏览器，可在确认无误后手动清理。”新前端**不会自动删除**旧数据。

## 12. 需要下一条消息（官方 Harness 接口与数据契约）回答的问题

1. **插件嵌入形态**：iframe、webview 还是组件挂载？面板的宽高范围？是否有入口路径或 `base` 约束？→ 决定 §7.4
2. **模型能力**：是否支持流式输出？消息格式？是否有工具调用或检索能力？能否展示模型名？有没有调用配额或错误码？→ 决定 §4.7、§7.3
3. **身份**：能否拿到当前用户的 ID 和显示名，用于执行人和审计？→ §6.6
4. **主题与导航信号**：宿主是否下发明暗主题？是否支持深链？
5. **服务端资源与字段**：编号规则、版本号/ETag、409 冲突的返回体、回收站、字段级 provenance 的存储方式、样本位置是否建模、附件存储。
6. **搜索**：支持哪些实体和过滤条件？是否返回高亮片段？
7. **导入导出**：是否支持 dry-run？导入时的冲突策略？导出的 schema 版本规则？
8. **部署同源性**：新前端与旧版是否同源？决定“从本浏览器迁移”能否直接读取旧数据（§9）。

## 13. 风险与取舍
- **范围：** 首版只做“课题 → 记录 → SOP/样本”主干和助手；导图、日程、打印标签放到 P4 以后，避免重蹈旧版“功能多但都不可靠”的覆辙。
- **落章与修订**会增加一点操作成本，但这是实验记录可信的基础。可以用“完整性检查只提示不阻塞”加上快捷键来降低摩擦。
- **字体体积：** 两套中文子集字体（宋体标题、文楷品牌）需要控制在可接受的范围内。若超出预算，就把文楷只用在 SVG 字标和印章里（预先转成路径）。
- **离线：** 首版只保证不丢稿（草稿缓冲），不做离线优先同步。是否需要后者，取决于用户在实验室断网场景下的反馈。
