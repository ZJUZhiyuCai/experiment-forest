# 旧版数据迁移

浏览器按 origin（协议、域名、端口）隔离存储。本机 `localhost:3000`、`127.0.0.1:3000` 和线上站点的数据彼此不同。新插件不能直接读取另一个地址的旧数据。

1. 在旧版使用的浏览器和地址保留原数据，先下载备份。不要清除浏览器缓存或重新初始化记录。
2. 旧版本机应用可在同一地址打开 `/legacy-export.html`，点击“检查并下载备份”。若旧站尚未包含此工具，可在旧站开发者控制台运行仓库 `public/legacy-export.js` 的内容；该脚本只读取明确列出的业务键，生成本机下载，不联网、不修改原数据。不要把 API Key、聊天设置或整个 localStorage 发给他人。
3. 在新工作台打开数据导入，选择 JSON，先核对预览中的各类数量、冲突和警告，再执行合并。
4. 检查关键实验正文、课题关联、样本信息，并从新版再次导出备份。确认完整后仍建议保留原始文件。

新版接受旧 Settings 导出的 `{records,notes,sops}`、完整业务 localStorage 快照以及新版 JSON 导出。完整旧版快照还包括 `projects`、`samples`、`experiment_plans`、`sample_history` 等。旧样本历史、日程、待办和心情保留在导入存档原文中，暂不转换为新工作台可编辑条目。

缺少历史课题时，预览会提示并保留原 `projectId`，不会编造课题；无历史时间时使用明确提示的未知时间标记。旧 ID 按类型稳定映射，扩展字段保留在 `data` 与导入存档。非法日期、损坏的核心集合、重复 ID 和新旧记录冲突会拒绝导入，不做部分覆盖。导入档案过滤账户/凭据/聊天字段，备份文件仍应按科研资料妥善保管。

当前数据库上限为 10,000 条实体和 20 MiB（包括导入存档）；单条正文最多 1,048,576 字符。新版自由实验页的附件通过 Harness 附件存储保存，不放进 JSON。JSON 导入保留附件引用，但不能替代本体和当前 profile 的材料登记数据；跨设备仅导入 JSON 会显示材料未登记。达到上限时明确报错，不自动删除历史数据。
