# Experiment Forest：实验工具参照与本轮建议

取证日期：**2026-11-08，北京时间**。范围：公开官方文档、原作者仓库，以及本地 v0.1.0 源码；未访问用户实验数据、Harness profile 或密钥。以下区分“来源描述”和“本项目建议”；未安装、运行或背书这些第三方产品。

本文保留基于 v0.1.0 的调研与早期建议，不是当前功能清单。用户随后选择 **Harness 管理实验、Obsidian 阅读整理，连接后直接自动同步**；最终使用方式见 [Obsidian 使用说明](OBSIDIAN.md)。下面的手工导出建议已由这一方向取代，来源证据与取舍继续保留。

建议本轮完成一条个人科研闭环：**从 SOP 创建带固定来源的草稿 → 按步骤记录实际执行 → 今日工作台找出下一步 → 向 Harness 提供有边界的上下文并导出可阅读报告**。库存数量台账、多人审批和通用公式引擎留待后续。

## v0.1.0 已有基础与真实缺口

本地检查依据：[数据契约](../shared/model.ts)、[字段模型](../client/forest-model.ts)、[领域后端](../plugin/domain.ts)、[模型工具](../plugin/tools.ts)、[上下文复制](../client/CopyToDeepSeek.tsx)、[工作台](../client/views.tsx)。

- 已有六种实体、真实持久化、修订冲突、软归档、引用类型检查、原始迁移资料保留及 JSON 导入导出；本轮应复用这些能力。
- `record.data.sopId` 指向 SOP 当前实体，没有固定正文/修订快照；SOP 修改后无法仅靠该链接重现当时的方法。`revision` 没有相应历史实体集合。
- SOP 只有普通正文和版本文本，记录没有受校验的执行步骤、逐步观测或偏差。当前 completed 状态不表达每一步发生了什么。
- 计划已有 `plannedDate`、状态与 `relatedRecordId`，首页已有 AI 待核对和未分类条目，但没有跨课题“今日/逾期/下一步”聚合，也没有直接把计划执行落成记录的确定性操作。
- `forest_search` 最多返回 100 条，无翻页；`forest_read` 一次读取一整个实体。上下文复制只列最多 20 个关联条目的标题/ID/修订，要求模型再读取；没有有界、一致的关联上下文包和可阅读研究报告。完整 JSON 备份已有，不能把新报告称为完整备份。

## 推荐落地的四项能力

### 1. SOP → 实验草稿，固定本次方法来源（优先）

从 SOP 详情“按此 SOP 开始记录”；选择课题后生成可编辑草稿。Host 在同一读取边界捕获 SOP 的 ID、revision、标题、版本文本、正文和必要来源标记，保存为明确的来源快照，同时保留到当前 SOP 的链接。详情明确区分“本次依据的版本”与“当前 SOP”。依据 LabArchives 的固定版本链接和 RSpace 的选择性复用模式提出此方案，快照字段设计是本项目建议。

只复制方法与明确的静态说明；实验日期、样本实际用量、结果、结论、完成勾选都留给用户填写。已有草稿不覆盖；未批准或 AI 未核对 SOP 显示来源状态，不能因创建实例变成已批准。若来源是 AI，实例不能通过复制去掉未核对语义。保存仍走现有 revision/事务边界，失败或取消后不盲目重复创建。

最小验收：源 SOP 后续修改/归档不改旧记录快照；同名不同修订可辨；旧记录缺快照时明确显示“未记录所用版本”，不能用今天的 SOP 回填历史。

### 2. 轻量执行清单与逐步观测（优先，与第 1 项一起完成）

给 SOP 增加可选有序步骤，给记录保存独立执行副本。每步有稳定 ID、说明、完成状态及实际观测/偏差文本。详情显示完成数和下一未完成步；勾选与观察记录由用户操作保存，不由 AI 推定。eLabFTW 的下一步和 SciNote 的步骤—结果关联是设计参照。

既有自由正文保留；没有结构化步骤的 SOP 不做猜测性自动拆分。AI 可提出待核对步骤草稿，但不得写完成状态、伪造实测或自动批准。完成清单不自动等于实验成功或 AI 已核对；取消勾选也应是正常受版本检查的修改。

最小验收：步骤不会因源 SOP 调整而重排/消失；冲突保留本地输入；进度来自保存的步骤；编辑/导出完整保留未知旧 data 与来源快照。

### 3. 今日工作台：今天、逾期、进行中、待核对（低成本高频）

对已保存实体做只读聚合：今日计划、逾期未完成计划、进行中的记录步骤、AI 待核对。条目直达实际记录；“开始计划”可衔接创建记录并明确关联，不能仅显示一条成功通知。借鉴 Lab Kit 的个人计划入口及 WetenSchaap 的每日视图，而非复制整个项目管理系统。

日期按用户界面时区解释 date-only 字段；无日期计划另列“未排期”。取消/完成/归档不列逾期；不自动顺延日期，不自动把卡片变成事实。初版不做后台提醒、外部消息、设备预约或拖拽甘特图。

最小验收：午夜/跨时区边界、空日期、归档和取消规则有明确测试；聚合刷新不写数据。

### 4. 有界关联上下文 + 可携带研究报告（完成 Harness 闭环）

提供确定性的只读上下文：所选记录、课题、SOP 固定快照、关联样本、相关计划/笔记；每条包含 ID、revision、状态、来源、是否截断以及继续读取方式。按数量/字节限制与分页控制，超出时明确列出省略信息，避免模型把搜索前 100 条当全量。模型沿用宿主权限，不增加秘密自动同步或第二套模型密钥。

同一数据可导出人可读 Markdown（必要时附可打印 HTML）：方法来源、用户实际填入的步骤/观测、关联条目、AI 待核对标记与导出时间。它是研究记录的阅读快照，不是模型编造的总结；继续提供既有 JSON 完整备份。正文里的链接只是数据，导出不主动读取本机文件/云端资料。

此组合是本项目对关联记录、来源版本和可携带文本模式的推论；不声称参照产品提供同样的 Harness 工具。最小验收：同一快照重复导出内容稳定；空结果不补写；截断有标记/续读；归档关联和历史 SOP 快照不丢；HTML 若实现，须正确转义原文。

## 不在本轮照搬

- **库存扣减/浓度换算/自动配方**：先有单位、批次、守恒、纠错流水及幂等规则再做。当前样本只是引用与位置，不能加一个余额框就称库存管理。
- **机构级审计、签名、见证和多人 ACL**：当前同一 profile 为个人共享工作区，不具备其身份与存储保证；普通 revision 和 AI 人工核对不是电子签名或合规认证。
- **通用公式、化学数据库、任意模板代码、仪器接入、附件仓库**：需要独立的数据与安全边界，优先级低于把现有实验闭环做好。
- **平台的隐式覆盖/自动重排**：模板只生成新草稿；日期提示不更改历史；引用归档保留；继承原文不继承事实完成状态。

调研时的实施排序建议：**1 + 2 为本轮核心；3 使用现有日期模型并行完成；4 先做结构化上下文与 Markdown 导出**。若需要缩减，缩小报告格式数量，而不是省略来源快照、冲突保护或数据可携带性。以上均为建议，本文未改源码、未安装第三方插件、未推送或发布。

## 本轮用户补充后的实施方向

用户随后明确“Obsidian 阅读、整理资料，Harness 管理实验”，并选择直接自动同步。因此实现采用 Host 保存后自动更新已登记本机资料库的专用目录；一次连接后无需手工导出。保留 Markdown 属性、关联与反向链接、Bases 视图作为阅读组织方式。这里的反向链接用于导航，不是双向数据同步；Obsidian 修改不回写实验主数据，人工改动的镜像文件保留并提示冲突。此方向取代上文仅讨论导出的早期建议。
