# 0.1.0 验证记录

本次从原仓库 `a9903eb` 重构，按 DeepSeek 官方 Harness `0.2.2-rc.1` 的实际代码与运行时接入，参考源码版本为 `fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159`。验证环境为 macOS、Node.js 26、Chrome，日期为 2026-11-07 至 2026-11-08（北京时间）。目前只声明该 Harness 版本兼容。

## 已执行的验证

- 52 项自动化测试、TypeScript 类型检查与原生插件构建通过。
- 领域事务、版本冲突、重启持久化、损坏数据拒绝、写入失败及不确定结果重新读取。
- 六类资料的引用校验、旧数据稳定 ID 映射、原始字段留存、重复导入不覆盖、冲突时整批拒绝。
- 官方 Native 工具执行链上的输入/输出校验、权限拒绝、调用取消以及只允许 AI 创建待复核草稿。
- 官方 Cordis、Storage、RPC Gateway 和工具注册表的 Host 集成测试；全部九个 RPC 对非拥有者拒绝访问；不同 profile 保存隔离，卸载注销服务和工具。
- 独立官方运行时通过 CLI 安装 npm tarball，再验证实际 HTTP RPC、新建、导出、版本冲突、Host 重启、客户端启动清单与资源路由。该环境没有源码链接或依赖 overrides，Host 自身使用 zod 4.4.3，插件使用 zod 4.6.7。
- Chrome 中通过真实官方侧栏操作：迁移六类示例资料及关联；新建笔记；编辑记录、清空日期及 SOP 关联；整页刷新后读取已保存内容；搜索；归档；下载完整 JSON；再次预览导出文件显示六条均未变化；冲突文件拒绝导入；损坏 JSON 显示错误且现有数据仍在。
- 通过真实侧栏关闭标签后重新挂载，未保存标题和全文正确恢复；刷新触发浏览器 beforeunload 提醒；明确放弃后原始服务端内容未被修改。
- 真实工具产出的测试草稿显示正确 AI 来源；人工勾选复核后只改变 reviewStatus，来源及 draft 状态保留；超 20 MiB 文件在读取前被拒绝。
- 最终 Apple / Notion 视觉稿在真实 Harness 的 520 px 侧栏，以及 1440、1200、800、390、360 px 视口下检查；插件没有横向溢出。检查了浅色与深色、课题时间线、资料详情、关联跳转、编辑表单、保存栏和导入面板。
- 在最终视觉稿中编辑正文、保存、刷新与导出，核对保存内容及已清空字段仍正确；切换记录状态并恢复草稿；损坏 JSON 提示错误且数据保留；“复制给 DeepSeek”面板生成受支持的笔记草稿说明。原生状态选择框可聚焦，选择变更生效；未将自动化对系统弹出菜单的方向键操作计为通过。
- 正常操作未发现控制台错误；刻意重启开发 Host 时出现断连重试日志，恢复后侧栏正常同步。
- 保留旧前端的 `build:legacy` 构建通过，仍有旧版资源块体积提示。

所有浏览器资料均为明确标注的人工验收示例，没有使用真实科研数据。开发 Harness 禁用模型供应商和遥测；以上验证没有向 DeepSeek 发起模型请求。模型工具通过真实官方执行链验证，实际账号、具体模型选择和真实对话中的调用仍需使用者的 Harness 环境验证。

## 数据和功能边界

- 同一 profile 内使用单个 Host 进程。默认 JSON 存储没有跨进程锁，进程内写入队列和版本检查不等同于多进程数据库事务。
- 同一 profile 的会话共享科研资料；课题分类不是多租户权限隔离。
- 已保存资料在 Host；未保存草稿属于当前浏览器页面会话，不能当作持久备份。
- 正文按纯文本分段显示。附件管理、Markdown 富文本、历史修订浏览、多用户协作、思维导图和旧版日程编辑尚未实现。
- 旧版自动填入的 QC、验证标记只作为迁移原始数据保留并提示复核，不代表科学结论。
- `npm audit --omit=dev` 对本插件的生产依赖未报告漏洞；这不代表官方 Harness 和遗留开发依赖均已完成安全修复。
