# 0.3.1 验证记录

2026-11-08，在 macOS、Node.js 26、Chrome 与官方 DeepSeek Harness `0.2.2-rc.1` 上验收。基线为 0.3.0 / `3f1e5c5a6994deb0e47ca4c089beed691d8179f4`。本轮仅更新展示样式与提案展示结构；数据契约、存储、材料、模型工具和同步实现没有变更。

## 自动化与官方运行时

- **141 项测试通过**，TypeScript 类型检查、插件构建、官方 Host / Gateway smoke 通过。
- 回归继续覆盖自由混排、原始快照、自动保存与并发、提案来源及人工决定、材料登记与重试、原件保留、同步冲突与重启恢复。
- 最终两份前端源文件与远端 Claude 原稿 SHA-256 一致。分工与校验值见 [原稿与适配](LOCAL_ADAPTATIONS.md)。

## 实际浏览器检查

使用隔离的 HOME、DSH_HOME 与仅含软件样本的 Obsidian 测试资料库，没有访问或修改用户真实资料库。

1. 检查 1440 px 工作台、Harness 右侧栏，以及 360 / 420 px 窄屏。提案对照在空间充足时左右排列，窄屏上下排列；表格保留内部横向滚动。
2. 检查浅色、深色、键盘与减少动态效果。复选框空格切换、来源展开正常，焦点环可见；高对比度模拟下三枚复选框均实际回退为 `appearance: auto`，装饰对勾关闭。减少动态效果下过渡为 1 ms。
3. 复核自绘复选框的最终渲染色：浅色边线与白底对比约 3.62:1，深色边线与 `#222` 底对比约 4.88:1；焦点分别约 5.39:1、6.22:1。
4. 编辑一处提案，再用“按我改的接受”提交；正文出现人工修改版本和待核对标记，确认后保存核对时间。另一次选择两处提案并拒绝，正文输入值逐一保持不变。
5. 修改表格单元格、在底部输入栏追加文字、上传 CSV。实际 Host 返回保存内容，新文件登记完成，原始 TSV 仍保留。
6. 点击“理一理”，通过当前 Harness 原生会话、真实读取与提案工具收到新提案。测试使用本机确定性模拟模型，没有外部模型请求，不代表模型的科学理解能力。
7. 上述保存与上传后，Obsidian 测试库自动出现正文和单元格修改；状态为已同步，**7/7 份材料与输入原件字节一致**。没有手动导出或触发立即同步。
8. 检查林地、今天、SOP 执行清单和同步面板；滚动到正文末尾后，最后内容块完整位于输入托盘渐隐区上方。

## 发布包安装

最终 0.3.1 tarball 在独立官方运行时用 CLI 安装验证，无源码链接、无依赖 overrides。检查实际 HTTP RPC、混排页面、材料分块上传与哈希、重启后的登记与读取、已有 SOP 流程、客户端清单和资源路由。此环境不连接用户资料库、不发起模型请求。

## 功能边界与历史证据

完整自由记录 → AI 提案 → Obsidian 流程及数据保护的历史验证见 [0.3.0 验证记录](VERIFICATION-v0.3.md)。当前安装、容量限制和备份方式以 [README](../README.md) 为准。

Obsidian 仍为同机可访问资料库的单向自动同步；不包含 Obsidian 编辑回写、独立跨设备同步或自动提醒。模型提案须人工决定，来源记录不证明内容正确。PDF、XLSX、视频和仪器文件可保存与同步，本版不解析其内部内容。
